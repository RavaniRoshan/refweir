The `refweird` server daemon is configured primarily through environment variables (`REFWEIR_*`), while offline administrative tasks utilize CLI subcommands (`refweird bootstrap`).

## Server Daemon (`refweird`)

### Environment Variables

| Variable | Default | Description |
| :--- | :--- | :--- |
| `REFWEIR_LISTEN_ADDR` | `127.0.0.1:8080` | Network address and port to bind the HTTP REST, MCP, and Web server |
| `REFWEIR_PUBLIC_URL` | `http://127.0.0.1:8080` | Publicly reachable base URL used for webhook callbacks and clone URLs |
| `REFWEIR_GIT_URL` | `127.0.0.1:8080` | Public host string returned in clone URLs |
| `REFWEIR_DATA_DIR` | `data` | Directory where SQLite metadata, Git repos, and audit logs are stored |
| `REFWEIR_SSH_ADDR` | `127.0.0.1:2222` | Network address and port for the embedded pure-Go SSH server (set to `none` to disable) |
| `REFWEIR_SSH_HOST_KEY` | `<data-dir>/ssh_host_key` | Path to the SSH host key PEM file for the embedded server |
| `REFWEIR_JWT_SECRET` | *(auto-generated)* | HMAC-SHA256 signing secret for capability leases and JWT sessions (min 32 bytes) |
| `REFWEIR_AUDIT_LOG` | `<data-dir>/audit.log` | Append-only JSONL audit log path. Set to `off` to disable the file; events stay on stderr and in memory. |
| `REFWEIR_DEMO_MODE` | `0` | Set to `1` to enable the hosted-demo surface and rate-limited demo run endpoint |
| `REFWEIR_DEMO_REPO` | `demo/agent-lab` | Target repository for hosted demo runs |
| `REFWEIR_CONFIG` | `refweir.toml` | Path to an optional TOML configuration file |
| `REFWEIR_TELEMETRY_OPT_IN` | `0` | Anonymous activation telemetry opt-in flag |

### Configuration File (`refweir.toml`)

Alternatively, `refweird` can read configuration from a `refweir.toml` file located in the working directory or specified via `REFWEIR_CONFIG`:

```toml
[transport]
http = ":8080"
ssh = ":2222"
public_url = "http://127.0.0.1:8080"
git_url = "127.0.0.1:8080"

[agentlease]
secret = "min-32-character-secret-signing-key-for-leases"
algorithm = "HMAC-SHA256"
ttl = "1h"
refs = ["refs/heads/agent/*"]

[smtp]
host = "smtp.example.com"
port = 587
username = "smtp-user"
password = "smtp-password"
from = "noreply@refweir.dev"
tls = true

[telemetry]
enabled = false
endpoint = "https://telemetry.example.com"

[cluster]
role = "primary"
node_id = "node-01"

[mcp]
endpoint = "/mcp"

[agentreviewer]
ast_analysis = true
secret_scan = true
min_coverage = 0.80
human_approval = false
```

Environment variables always take precedence over values in `refweir.toml`.

### Subcommand: `bootstrap`

Used for offline, one-time initialization of the SQLite database and creation of the primary administrator account:

```bash
refweird bootstrap \
  --email <admin-email> \
  --namespace <namespace-slug> \
  [--data-dir <path>]
```

| Flag | Required | Default | Description |
| :--- | :--- | :--- | :--- |
| `--email` | Yes | (none) | Email address for the root administrator account |
| `--namespace` | Yes | (none) | Namespace slug to create for the initial workspace |
| `--data-dir` | No | `./data` | Target directory for database and storage |

## On-Disk Storage Layout

When `REFWEIR_DATA_DIR` is configured (for example, `./data`), `refweird` organizes files in the following structure:

```text
data/
├── meta.db          # Primary SQLite metadata database
├── meta.db-wal      # SQLite Write-Ahead Log
├── meta.db-shm      # SQLite shared memory file
├── audit.log        # Append-only JSONL audit trail
├── ssh_host_key     # Auto-generated SSH host private key
└── git/             # Bare Git repositories managed via host git backend
    └── acme/
        ├── demo-app.git/
        └── backend.git/
```

- **`meta.db`**: Stores users, password hashes, web sessions, tokens, namespaces, repository records, permissions, pull requests, review comments, status checks, rulesets, and notifications.
- **`audit.log`**: Append-only JSON Lines file written by the daemon and pre-receive hook. Records actor, action, resource, severity, and capability lease metadata.
- **`git/{owner}/{repo}.git`**: Bare Git repositories storing Git objects and refs.

## SQLite Pragmas & Concurrency

`refweird` automatically applies the following database pragmas upon connection:

- `PRAGMA journal_mode = WAL`: Write-Ahead Logging allows concurrent readers alongside active writers.
- `PRAGMA busy_timeout = 5000`: 5-second wait on lock contention before returning busy error.
- `PRAGMA foreign_keys = ON`: Strict relational integrity for cascading deletes and reference checks.
- `_txlock=immediate`: Write transactions execute `BEGIN IMMEDIATE` to prevent lock escalation deadlocks under concurrent multi-agent traffic.
